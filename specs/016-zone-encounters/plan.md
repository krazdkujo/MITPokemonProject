# Implementation Plan: Zone-Based Pokemon Encounters

**Branch**: `016-zone-encounters` | **Date**: 2026-01-04 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/016-zone-encounters/spec.md`

## Summary

Implement a zone-based encounter system that organizes wild Pokemon by terrain type (Water, Fire, Grass, etc.) with difficulty tiers (Easy, Medium, Hard, Expert). The system uses all 1142 Pokemon from Source data, maps them to appropriate zones based on type and SR rating, and persists battle state to the database for seamless resume across browser sessions.

Key technical decisions:
- Zone configuration stored in Source/zones.json (static reference data)
- New `active_battles` database table with JSONB state column
- Type-to-terrain mapping covers all 18 Pokemon types across 8 terrain categories
- Battle created on zone confirmation, persisted after each action
- Seamless auto-resume when player returns to combat page

## Technical Context

**Language/Version**: JavaScript (ES2020+) with Node.js 18+
**Primary Dependencies**: Next.js 14, React 18, @supabase/supabase-js
**Storage**: Supabase PostgreSQL (new active_battles table) + Source JSON files
**Testing**: Jest (unit), Supertest (API), Cypress (E2E)
**Target Platform**: Web (Vercel serverless)
**Project Type**: Web application (Next.js)
**Performance Goals**: <200ms API response, <1s page load
**Constraints**: 10-second serverless timeout, stateless requests, RLS required
**Scale/Scope**: 1142 Pokemon, 24+ zones (8 terrain x 3+ difficulty)
